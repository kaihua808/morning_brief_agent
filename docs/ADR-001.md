# ADR-001｜延迟基金数据采用阻断策略

> 状态：Accepted
> 决策日期：2026-09-01
> 适用版本：基金晨报 MVP v0.1

## 背景

基金历史净值本身可能正确，但数据日期可能落后于用户以为的“当前行情”。BC-001 中，本地数据停留在 `2026-08-20`，到 `2026-08-31` 已相差 11 个自然日；旧程序仍然计算并输出近期指标。

该产品用于帮助用户减少情绪化判断，不是交易系统。即便如此，把旧数据包装成正常晨报仍可能误导用户。

## 决策

基金晨报 MVP v0.1 采用保守阻断策略：

```text
数据新鲜且校验通过
→ data_status: normal
→ calculation_status: completed
→ 允许计算、Model 解释和 HTML 输出

数据超过当前新鲜度阈值
→ data_status: delayed
→ calculation_status: blocked
→ metrics: null
→ 不进入正常 Model 解读
```

自动刷新失败时同样返回 `refresh_failed + blocked`，并保留原 CSV，不用坏的候选数据覆盖本地文件。

## 选择理由

1. 用户不能只凭页面文字判断数据是否仍代表当前市场。
2. Model 的自然语言会增强旧数据的可信感，必须在进入解释层之前阻断。
3. MVP 只有单基金和单一本地数据源，没有足够可靠的交易日历与降级规则。
4. 金融场景下，暂时没有报告比生成一份可能被误认为最新的报告风险更低。
5. 阻断逻辑简单、可测试，符合当前项目的最小范围。

## 考虑过的替代方案

### 方案 A：继续计算，只显示过期警告

优点：即使接口失败，用户仍能看到历史指标。

缺点：用户可能忽略警告；Model 解释会让旧指标看起来像今日结论。

当前不采用。

### 方案 B：自动使用上一份成功报告

优点：页面始终有内容。

缺点：进一步隐藏了数据年龄，而且旧报告中的文字与当前日期容易混淆。

当前不采用。

### 方案 C：按交易日落后程度分级降级

```text
落后少量交易日 → 醒目标注并允许展示历史指标
落后超过阈值   → blocked
```

这是更合理的后续方向，但依赖可靠交易日历、基金披露时间和明确的页面状态设计，超出 v0.1 范围。

## 结果与代价

正面结果：

- 旧数据不会被生成成正常晨报；
- 数据问题在 Python 层暴露，不交给 Model 猜测；
- 可以用延迟固件稳定回归；
- 刷新失败不会破坏最后一份可信 CSV。

接受的代价：

- 长假期间可能因为自然日阈值误报并停止服务；
- 短暂网络错误也会让本次晨报不可用；
- 用户暂时看不到“带明确过期标签的历史指标”。

## 验证方式

- 延迟固件：`data/fixtures/006131_delayed.csv`
- 状态测试：`test_delayed_data_is_blocked`
- 边界测试：`test_four_day_boundary_is_normal`、`test_five_day_boundary_is_delayed`
- 刷新失败测试：`test_refresh_failure_blocks_metric_calculation`
- 产品评测：`docs/evaluation_report.md` 中 EV-006、EV-007

## 重新评估条件

满足以下条件后重新讨论阻断与降级：

1. 接入并本地保存可靠的 A 股交易日历；
2. 能算出“当前应已公布的最新基金净值日”；
3. HTML 能明确区分正常、延迟但可读、完全阻断三种状态；
4. 对长假、披露延迟和刷新失败建立独立测试；
5. 通过真实用户评测确认过期标签不会被忽略。

在这些条件满足前，继续使用 `delayed / refresh_failed → blocked`。
